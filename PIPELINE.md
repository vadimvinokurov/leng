# PIPELINE (Leng)

Конвейер работы агента над фичей. Подробности и обоснования — PROJECT.md §11,
CLAUDE.md (правила работы).

## Гейты (все обязательны, выход не нуля = красный)

- `./scripts/test.sh` — pytest + ruff + mypy --strict (бэкенд), fmt + clippy +
  cargo test (клиент). CWD-независимый.
- `./scripts/golden.sh` — golden-path e2e бэкенда (compose test-профиль).

## Шаблон приёмки фичи (каждая фича MVP-2/3+)

1. Фича = команда реестра + валидация из схемы (без ручных кнопок мимо /v1).
2. Оптимизация — наивный оракул в tests/oracles.py, тест дельты.
3. Golden-выход до интеграции, минимум один hand-computed кейс.
4. Полный гейт зелёный.
5. Новое состояние доступно headless (/v1/state, leng-cli); новый рендер —
   чистая функция с golden.
6. GUI без логики; headless-изоляция ядра охраняется purity-тестом; ручной
   чек-лист — только фокус/хоткей/пермиссии.

## Порядок работы над фичей (CLAUDE.md §4)

RED (тест до кода, падает по ожидаемой причине) → GREEN (минимум кода) →
REFACTOR (тесты зелёные) → полный гейт → golden.sh при изменении HTTP-контракта
→ коммит (тема < 72 chars, объясняет «почему»).

сразу переносятся в соответствующий раздел PROJECT.md.
